# 实验九方案 v3（定稿）：友好型源网荷储一体化规划配置仿真平台

> 版本：v3（2026-10-20）
> 本版依据工作区新增的 `data/raw/源网荷储一体化仿真数据/` 与“机器学习涉及算法、神经网络、需可扩展”的要求定稿。
> 交付原则：Windows 本机演示必须跑通；服务器/Docker/公网为加分项；三张参考界面核心信息必须还原；机器学习做成可插拔模块，不阻塞主线。

---

## 0. 结论摘要

路线：**Vue3 + FastAPI + Python 分析/算法模块 + SQLite（本机）/ MySQL 或 Postgres（服务器）**。本机一键启动，服务器 Docker 部署；不整套引入 jeecg-boot。

**项目实际数据**：华东沿海工业园，2026 年 1 月 1 日—8 月 31 日，小时级 5832 点；基础方案 50 MW 风电 / 80 MW 光伏 / 20 MW·80 MWh 储能；优化参考结果 80 MW 风电 / 120 MW 光伏 / 40 MW·160 MWh 储能 / 70 MW 外网。8 个月负荷电量 327.5 GWh，年化约 491 GWh，峰值 79.2 MW。界面默认值用这套真实数据，不再用 680 GWh/140 MW 的旧假设。

| 类别 | 内容 |
|---|---|
| 必须 | 三张参考界面、CSV/Excel 上传与体检、容量优化、运行仿真、指标、Word 报告、Windows 一键启动 |
| 加分 | Docker、公网 HTTPS、登录、机器学习/神经网络、多方案对比、敏感性 |
| 可扩展 | 模型注册表、训练/预测 API、实验记录、ONNX/PyTorch 适配位 |

七条主线：

1. **数据**：教师数据为主；先做“数据盘点 + 血缘 + 冲突检测”，再谈建模。该数据集内部存在若干不一致，平台要显式暴露，不能静默合并。
2. **分析**：Jupyter + NumPy/Pandas/SciPy/Matplotlib/Seaborn，完成清洗、描述性分析、典型日、指标。
3. **优化**：`scipy.optimize.linprog(method="highs")` 解典型日容量规划；全年规则调度；15 分钟可选 96 点。
4. **后端**：FastAPI + SQLAlchemy + SQLite；项目、数据、体检、仿真、报告、ML 六组接口。
5. **前端**：Vue 3.5 + Vite 7 + Element Plus + ECharts 5.6；数据、大屏、报告三页优先，配置/对比/模型实验加分。
6. **部署**：本机 `start.ps1` 一键；服务器 Docker Compose；公网加 Nginx/Caddy + HTTPS + 登录。
7. **机器学习**：算法 + 神经网络可插拔；sklearn 基线（RF/HGB/MLP）默认可用，PyTorch LSTM/GRU/Transformer 作为可选扩展；不接大模型 API。

### 2.2 数据血缘（重要）

```
01/02/07/08  ──参数──┐
                      ▼

                      │
04 典型日（15min）─────┘  展示样例
```

规则：

- 上传多个文件时，平台显示“角色 + 版本 + 来源”，并做跨文件一致性检查；冲突不静默覆盖。

### 4.2 上传即体检

**流程**

1. 接收 CSV/XLSX，≤50 MB、≤10 万行；保存原始文件 + SHA-256。
2. 识别编码、分隔符、表头、时间列、间隔（15/30/60 分钟）。
3. 推断字段，给出映射建议；用户可改。
4. 质量检查，返回 `status/score/blocking/warnings/columns/preview`。
5. 确认后导入；体检不通过禁止进入仿真。

**检查项**

| 类别 | 检查 | 级别 |
|---|---|---|
| 时间 | 无时间列、无法解析 | 阻断 |
| 时间 | 覆盖 <24h、间隔不支持 | 阻断 |
| 时间 | 缺口、重复、乱序 | 警告/阻断 |
| 完整 | 缺失率、连续缺失 | 警告 |
| 范围 | 风速、辐照、温度、负荷、SOC | 警告 |
| 一致 | 夜间 PV 为负、馈线/平衡误差 | 警告 |
| 单位 | kW/MW、kWh/MWh、元/kWh | 警告 |
| 跨文件 | 同一时间范围数值冲突 | 警告 |

**返回示例**

```json
{
  "dataset_id": "ds_001",
  "status": "usable_with_warnings",
  "score": 82,
  "rows": 5832,
  "time": {"start": "2026-01-01T00:00:00", "end": "2026-08-31T23:00:00",
           "interval_minutes": 60, "coverage": 0.666},
  "blocking": [],
  "warnings": [
    {"code": "PARTIAL_YEAR", "message": "仅覆盖 8 个月，年指标需标注年化估算"},
    {"code": "PRICE_MISMATCH", "message": "文件电价与 07 分时模板不一致"},
    {"code": "CROSS_FILE_LOAD", "message": "与 05 的负荷范围差异较大"}
  ],
  "columns": [{"source": "风速(m/s)", "target": "wind_speed_m_s", "unit": "m/s", "status": "matched"}]
}
```

**评分基线**

```
score = 100
  - 非法时间比例×200（上限20）
  - 重复比例×200（上限15）
  - 关键列缺失率×150（上限20）
  - 缺口段数×2（上限15）
  - 异常比例×100（上限10）
  - 物理越界条数×3（上限20）
```

`usable`：无阻断且 score ≥60；`usable_with_warnings` 可导入；`unusable` 先修。

### 4.4 清洗 8 步

1. **读取**：CSV `utf-8-sig`；Excel `openpyxl`；列名清洗；原始只读。
2. **时间**：统一时区；识别间隔；检查重复/缺口/乱序；8 个月数据标“部分年”。
3. **缺失**：≤3 点线性插值；更长用同月同时段均值；关键列缺失 >20% 不建模。
4. **异常**：物理阈值 + IQR 三倍；夜间 PV 负数、SOC 越界、平衡误差 >1% 标记。
5. **重复一致**：重复保留最后；校验 `风+光+储放+购=负荷+储充+上网+弃`，容差 1%。
6. **重采样**：15 分钟→1 小时取均值；1 小时不升采样；展示需插值时标注。
7. **派生**：风机曲线 3/11/25 m/s；PV 效率 0.82；储能效率 0.92；温度修正。
8. **质量报告**：`quality_report.json`，前端展示。

### 4.5 描述性分析

至少 8 图：基本统计、月度资源、24h 箱线、月×时热力图、持续曲线、相关性、Weibull、负荷特性/典型日。结论回答：风光互补、峰谷错位、储能时段、典型日误差。

### 4.6 典型日

- 按月平均日：12×24 或 12×96。
- KMeans：24/96 维归一化聚类，取类中心最近日期。
- 误差比较：年电量、峰值、谷值；默认 1h 优化，15 分钟可选。
- 04 只有光/荷，典型日页需标注“无风电”，或从 03 补风电。

### 4.7 规模

- 1h：5832 行（8 个月）；15min：23328 行（8 个月）。
- SQLite 足够；前端 LTTB 降采样；默认典型日。
- 指标区分“期间值/年化估算”。

## 5. 模型与算法

### 5.1 流程

```
03 输入 → 清洗 → 典型日 → LP 容量 → 全年规则仿真 → 指标
        → 05/06 对照 → 多方案/敏感性 → 推荐
        → ML：异常检测/聚类/预测 → 模型实验页
```

### 5.2 容量优化 LP

**参数（来自 01/02/07/08）**

- 风电 6500 元/kW，光伏 3500 元/kW，储能 1200 元/kWh；折现 8%；碳价 80 元/t。
- 电价：谷 0.35、平 0.75、峰 1.15；上网 0.35。
- 储能效率 0.92；SOC 10%–95%；风机切入 3、额定 11 m/s；PV 效率 0.82。

**变量**：`C_w, C_pv, C_b, E_b`；逐时 `g_in, g_out, ch, dis, e, cur_w, cur_pv, unserved`。

**目标**

```
min Σ_t w_t (price_buy·g_in - price_sell·g_out + VOLL·unserved + c_cur·curtail)
    + c_w·C_w + c_pv·C_pv + c_b·C_b + c_e·E_b
```

**约束**：功率平衡、SOC 递推、SOC 上下限、日循环、充放上限、弃电上限、外网容量、消纳率、储能时长 2–6h、容量边界。

**线性化**：用 `e` 代替 `SOC×E_b`；同时充放电用吞吐成本抑制，必要时 MILP。LCOE 事后算。

**规模**：12×24 约 2300 变量，0.1s；12×96 约 9000 变量；全年 8760 LP 可选不默认。

### 5.3 全年仿真

优先风光→负荷；富余充储→上网→弃；缺额放储→购电→未供电；谷充峰放；记录逐时曲线。与 05/06 对照，解释差异。

### 5.4 指标

绿电占比、消纳率、LCOE、可靠率、峰谷差率、削峰率、碳减排、NPV/IRR/回收期、友好性五维。

### 5.5 多方案与敏感性

经济/低碳/高可靠/均衡；投资、电价、负荷、资源、折现率敏感性；龙卷风图。

### 5.6 机器学习与神经网络（可扩展）

#### 5.6.1 定位

老师提到“机器学习与算法、神经网络有关”。本方案把 ML 做成**独立可插拔层**，不侵入优化主链路：

- P0：数据异常检测（IsolationForest + 规则）——服务上传体检。
- P0：典型日聚类（KMeans）——服务场景缩减。
- P1：负荷/光伏/风电短期预测——服务“预测 vs 实际”和调度参考。
- P2（可选）：优化代理模型、强化学习调度——只留接口，不做。

> **实际落地（2026-10-22）**：为满足“用网络数据集训练 ML，再分析给定数据”的明确要求，先实现“公开光伏数据 → 光伏容量因子 CF → 迁移到 03”的回归链路（`src/ml/pv.py`、`/api/ml/pv`、前端“机器学习”页），而不是本节的负荷预测/异常检测全套。异常检测目前仍是规则体检，KMeans 典型日与神经网络未做；详见 `docs/机器学习.md`。

#### 5.6.2 数据结构

- 输入：时间序列 + 外生变量（温度、辐照、风速、电价、日历）。
- 目标：`load_mw`、`pv_mw`、`wind_mw`；默认 24h 预测，可配 15min×96。
- 切分：按时间 70/15/15 或最后 20% 测试，禁止随机打乱。
- 特征：小时/星期/月份、滞后 24/48/168、滚动均值/标准差、温度/辐照/风速。
- 指标：MAE、RMSE、MAPE、R²；预测图 + 残差图。

#### 5.6.3 模型注册表

```
src/ml/
├─ base.py          BaseForecaster: fit/predict/save/load/params
├─ registry.py      @register("lstm")；按名字创建
├─ features.py      时间特征、滞后、滚动、缩放
├─ datasets.py      窗口化、切分
├─ train.py         训练、早停、指标、产物
├─ predict.py       推理
├─ anomaly.py       IsolationForest + 规则
├─ cluster.py       KMeans 典型日
└─ models/
   ├─ baselines.py  persistence / seasonal_naive / linear
   ├─ classical.py  RandomForest / HistGradientBoosting
   ├─ mlp.py        sklearn MLPRegressor
   └─ torch_nn.py   LSTM/GRU/Transformer（可选依赖）
```

新增模型只需：继承 `BaseForecaster` + `@register("name")`，不改 API/前端/训练器。这是“可拓展性”的核心。

#### 5.6.4 依赖策略

- 默认：scikit-learn（已装）即可跑 RandomForest、HGB、MLP，满足“算法 + 神经网络”演示。
- 可选：`pip install torch`（PyPI 有 cp314 win wheel，CPU 版）启用 LSTM/GRU；未安装时页面显示“未启用”，不报错。
- 不引入 TensorFlow/Keras，减少体积与版本冲突。
- 模型产物：`models/{run_id}/model.joblib` 或 `model.pt` + `config.json` + `metrics.json`。
- 可选导出 ONNX，便于部署；不作为主线。

#### 5.6.5 API 与页面

- `GET /api/ml/models`：返回可用模型及依赖状态。
- `POST /api/ml/runs`：目标、模型、超参、切分、特征。
- `GET /api/ml/runs/{id}`：状态、指标、产物路径。
- `POST /api/ml/runs/{id}/predict`：返回预测序列。
- 前端 `/project/:id/ml`：模型选择、训练、指标表、预测图、残差图、模型对比。

#### 5.6.6 数据现实

5832 小时（8 个月）足够做单步/24h 预测的课程演示，但不足以训练大型深度网络；报告要写“数据长度限制、过拟合风险、仅课程验证”。若老师后续给更长数据，接口不变。

#### 5.6.7 大模型 API

不做依赖。保留 `backend/services/llm.py` 默认关闭的接口位；key 只放后端 `.env`；报告模板不依赖。老师明确要“大模型问答/润色”再加。

### 5.7 假设与局限

部分年、典型日近似、无潮流、效率固定、成本线性、碳因子平均、规则调度非最优、数据版本不一致。报告写清楚。
