# 项目展示说明

> 目标：在答辩现场用 5–8 分钟完整展示平台，操作路径固定、结果可预期、失败有兜底。技术细节见 `docs/项目实现说明.md`，口播内容见 `docs/答辩说明.md`。

## 1. 展示前准备

### 1.1 启动服务

在项目根目录 `源网荷储一体化仿真平台` 打开 PowerShell：

```powershell
.\deploy\start.ps1
```

看到类似输出后，浏览器打开：

```text
http://127.0.0.1:8000/
```

如果已经手动启动后端，也可以直接运行：

```powershell
.\.venv\Scripts\python.exe -m uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

### 1.2 检查三件事

1. 页面右上角显示“运行中”，左下角显示“后端服务在线”；
2. 运行总览的 6 个指标卡有数字，典型日图有柱状和折线；
3. 浏览器控制台没有红色报错。

如果右上角显示“离线”，先访问 `http://127.0.0.1:8000/api/health`，确认返回 `{"status":"ok",...}`。

### 1.3 现场建议

- 用 **1440×900 以上**窗口，浏览器缩放 100%；
- 提前打开五个页面各一次，让图表完成首次渲染；
- 不在现场跑 30×30 优化（约 20 分钟），用预计算参考；
- 数据上传演示用教师原始 CSV，不用临时改过的文件；
- 准备一张运行总览截图，防止现场网络/端口异常。

## 2. 推荐展示路线（5–8 分钟）

| 顺序 | 页面 | 动作 | 讲解重点 |
|---|---|---|---|
| 1 | 运行总览 | 保持默认“基准 50/80/20/80” | 6 个指标、典型日平衡、SOC、月度电量 |
| 2 | 运行总览 | 点击“优化参考 80/120/40/160” | 成本上升，但弃电下降、SOC 进入区间 |
| 3 | 容量优化 | 展示“预计算参考” | PSO 结果 87.7/167.7/0/0、16,802 万元、零储能 |
| 4 | 数据管理 | 上传 03 CSV | 5832 行、时间轴连续、评分 90、问题清单 |
| 5 | 机器学习 | 直接展示 | 外部 R² 0.9964、03 迁移 CF 0.269 vs 0.234 |
| 6 | 报告输出 | 选择基准方案，下载 HTML | 报告可带走、可打印 PDF |
| 7 | 总结 | 回到总览 | 经济最优 vs 友好配置的取舍 |

如果时间只有 3 分钟：只讲总览 → 容量优化参考 → 报告输出，数据管理和机器学习各用一句话带过。

## 3. 运行总览：怎么操作、看什么

### 3.1 默认基准方案

打开页面后默认是：

- 场景 A · 小时级规划数据；
- 容量 50/80/20/80 MW；
- 六个指标卡：年化总成本、LCOE、弃电率、绿电占比、供电可靠率、SOC 软区间占比。

预期值：

| 指标 | 数值 |
|---|---:|
| 年化总成本 | 2.134 亿元/年（21,340 万元） |
| LCOE | 0.503 元/kWh |
| 弃电率 | 0.0% |
| 绿电占比 | 53.2% |
| 供电可靠率 | 100.000% |
| SOC 软区间占比 | 52.8% |

讲解顺序：

1. 先指年化总成本：这是“投资年化 + 运维 + 购电 − 售电 + 碳成本”的综合；
2. 再指弃电率和绿电占比：基准方案弃电为 0，但绿电占比只有 53.2%，说明还需要外网购电；
3. 指典型日图：蓝色风电、黄色光伏、紫色储能放电、橙色购电叠加后要托住白色负荷线；
4. 指 SOC 图：储能夜间充电、白天放电，SOC 在 30%–80% 附近波动；
5. 指月度图：1—8 月每月电量结构，注意这是实际覆盖月份，不做全年伪造。

### 3.2 切换参考方案

点击“优化参考 80/120/40/160”，等待 1–2 秒。预期：

- 年化成本约 1.876 亿元；
- 弃电率约 0.03%；
- SOC 软区间占比约 43.8%；
- 光伏和储能明显增大。

讲解句：

> 这是增加风光储容量后的友好配置。成本比基准高，但弃电几乎为零，储能也更多时间落在 30%–80% 区间。它和后面的 PSO 经济最优形成对照。

### 3.3 切换场景 B（可选）

把“数据场景”切到“场景 B · 基准运行数据”，保持 50/80/20/80。预期：

- 年化成本约 2.807 亿元；
- 弃电率 0；
- 供电可靠率略低于 100%，因为 05 数据的购电峰值超过 70 MW 外网限值。

讲解句：

> 场景 B 是教师给的基准运行结果，负荷和资源与场景 A 不一致，所以只做对照，不和 A 合并。

## 4. 容量优化：怎么操作、看什么

### 4.1 展示预计算参考（推荐）

进入“容量优化”，右侧“预计算参考”直接显示：

- 最优容量：87.7 / 167.7 / 0.0 MW / 0.0 MWh；
- 年化总成本：16,802.1 万元/年；
- 弃电率：3.9%；
- 绿电占比：65.7%；
- SOC 软区间：0.0%；
- 计算耗时：1368.3 s；
- 算法：PSO 30×30，seed 3。

讲解顺序：

1. 先读容量：风电 87.7 MW、光伏 167.7 MW、储能 0；
2. 再读成本：比基准低约 4,538 万元/年；
3. 主动解释零储能：外网 70 MW 能保供、储能投资高、长时段弃电靠短时储能消不掉；
4. 指“运行记录”：SQLite 里保存了每次优化，刷新页面不会丢；
5. 强调现场不跑 30×30，预计算是真实跑出来的结果。

### 4.2 在线跑一个小规模优化（可选）

如果老师想看“真的在算”：

1. 场景选 A；
2. 算法选 PSO；
3. 粒子/狼群数 12，迭代 8，种子 42；
4. 点击“开始优化”。

预期几秒内返回，结果可能仍是零储能或很小储能；页面会写入一条新的运行记录。不要在答辩现场跑 30×30。

讲解句：

> 每个候选解都要跑 5832 小时规则调度，单次约 20 ms；12×8 是 96 次评估，几秒完成。30×30 是 900 次，约 20 分钟，所以现场用预计算。

### 4.3 切换到 GWO（可选）

算法选“GWO 灰狼群”，同样 12×8。预期结果与 PSO 接近，可能保留很小的储能。讲解句：

> 两种算法的搜索机制不同，但成本只差十几万元，说明经济最优附近比较平坦。

## 5. 数据管理：怎么操作、看什么

### 5.1 上传文件

1. 进入“数据管理”；
2. 点击上传区，选择：

```text
源网荷储一体化仿真平台\data\raw\源网荷储一体化仿真数据\03_小时级源荷气象电价数据.csv
```

3. 等待 1–2 秒。

### 5.2 预期体检结果

| 项目 | 预期 |
|---|---|
| 行数 | 5,832 |
| 时间范围 | 2026-01-01 00:00:00 → 2026-08-31 23:00:00 |
| 采样间隔 | 60 分钟 |
| 覆盖率 | 100% |
| 重复时间戳 | 0 |
| 时间缺口 | 0 |
| 评分 | 90 |
| 状态 | 可用，需清洗 |

页面还会显示：

- 列映射：时间、风速、GHI、温度、负荷、购电价等字段；
- 未映射列：原始文件中系统不使用的列；
- 前 5 行预览；
- 问题清单：评分 90 说明有提示项，通常是电价口径或字段范围提示，不是阻断。

### 5.3 讲解句

> 数据管理不是简单上传，而是先做时间轴、缺失、重复、物理范围检查。03 数据 5832 行、时间连续、覆盖率 100%，评分 90；它仍然有需要说明的口径问题，所以系统不把“能上传”等同于“能直接算”。

如果老师问“为什么不把 03 和 05 合并”，回答：

> 两份数据的负荷、温度、风速不逐行对应，按时间合并会制造虚假关系；系统把 A/B 作为两个场景分别计算。

## 6. 机器学习：怎么操作、看什么

进入“机器学习”，页面会自动加载模型信息和迁移对照，无需点击。

预期显示：

- 外部训练样本：3,157 行；
- 测试集 R²：0.9964；
- 测试集 MAE：0.0077；
- 03 迁移平均 CF：0.269；
- 物理口径平均 CF：0.234；
- 模型：RandomForestRegressor，240 棵树，最大深度 12；
- 数据来源：Kaggle Solar Power Generation Data（Plant 1）。

图表：

- 左侧典型日：GHI、物理 CF、ML CF 三条曲线；
- 右侧误差分布：ML − 物理，集中在 0 附近，有少量正偏差；
- 下方：物理口径 2.134 亿元/年、LCOE 0.503；ML 口径 1.964 亿元/年、LCOE 0.463。

讲解句：

> 这里用网络公开数据训练模型，再迁移到 03 数据。外部测试 R² 0.9964，迁移后两条 CF 曲线相关系数 0.9997。ML 口径成本低约 8%，但这是敏感性分析，不是目标电站的真实预测，主结果仍用物理口径。

如果老师追问“为什么不用 LSTM”：

> 外部数据只有 33 天、3,157 个有效点，深度时序模型容易过拟合；随机森林在表格特征上更稳，也更容易解释特征重要性。

- 项目概况；

讲解句：

> 报告不是静态模板，指标来自当前仿真结果；下载的 HTML 可以直接带走，打印后就是 PDF，方便提交。

## 8. 现场讲解顺序（可直接照读）

### 8.1 开场

> 我的项目是友好型源网荷储一体化规划配置仿真平台。它解决三个问题：数据能不能用、给定容量怎么运行、容量配多少最合适。

### 8.2 总览

> 默认是教师给的基准方案 50/80/20/80。年化成本 2.134 亿元，弃电率为 0，绿电占比 53.2%。典型日图里，风、光、储、购电叠加后托住负荷；SOC 图显示储能的充放电过程。

### 8.3 优化

> PSO 在场景 A 找到的经济最优是 87.7 MW 风电、167.7 MW 光伏、零储能，年化成本 1.68 亿元，比基准低约 4,538 万元。零储能不是 bug：外网 70 MW 能保供，储能投资高，长时段弃电靠短时储能消不掉。如果要求储能运行在 30%–80%，推荐 80/120/40/160 的友好配置，成本 1.876 亿元，弃电 0.03%。

### 8.4 数据

> 数据上传后会做时间轴、缺失、重复、物理范围检查。03 数据 5832 行、覆盖率 100%、评分 90。03 和 05 的负荷、资源不一致，所以系统分成两个场景，不按行合并。

### 8.5 机器学习

> 用 Kaggle 公开光伏数据训练随机森林，外部测试 R² 0.9964，再迁移到 03 数据。ML 和物理 CF 相关系数 0.9997，成本低约 8%，但只作敏感性分析。

### 8.6 收尾

> 平台把数据体检、仿真、优化、机器学习和报告串成闭环。本机可直接启动，服务器提供 Docker 方案。我的汇报到这里，谢谢老师。
