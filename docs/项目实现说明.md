# 项目实现说明

## 1. 项目定位

**友好型源网荷储一体化规划配置仿真平台**面向园区级源网荷储系统，完成从数据接入到方案评价的完整链路：

1. 读取并体检教师提供的小时级源荷气象数据、基准运行数据、设备与成本参数；
2. 在给定风电、光伏、储能容量下，逐时模拟系统运行，计算购电、售电、弃电、SOC 和各项指标；
3. 用 PSO/GWO 搜索年化总成本最低的容量组合；
4. 用外部公开光伏数据训练容量因子模型，迁移到本项目数据做对照分析；
5. 用 Vue3 页面展示运行总览、数据体检、机器学习、容量优化和报告输出；
6. 用 SQLite 保存优化运行摘要，用 FastAPI 同时提供 API 和前端静态资源。

项目的核心:把**数据质量、时序仿真、容量优化、机器学习**放在同一条可复现的计算链路上。

### 4.2 数据冲突与处理原则

教师数据包不是一套完全对齐的数据，已识别的冲突包括：

- 03 与 05 的负荷、温度、风速不逐行一致；
- 03 原始电价 0.32/0.45/0.85 与 07 分时模板 0.35/0.75/1.15 不一致；
- 04 典型日只有光伏和负荷，没有风电；
- 05 的弃电为 0，而 06 的参考弃电率为 3.5%；
- 06 的参考容量与 09 的草稿容量不一致；
- 数据只覆盖 1—8 月，不是完整 8760 小时。

处理原则：

1. **不按时间行合并 03 与 05**，分别构造场景 A、场景 B；
2. 电价统一使用 07 分时模板，03 原始电价保留作敏感性对照；
3. 06 只做参考，不把它的指标当作同一场景的精确答案；
4. 09 不采信；
5. 年化指标按 `8760 / 5832` 外推，并在报告与页面注明“样本年化”。

### 4.3 场景 A 构造

`src/loader.py` 的 `load_scenario_a()`：

1. 读取 `03_小时级源荷气象电价数据.csv`，按中文列名取数；
2. `pd.to_datetime(..., format="mixed")` 解析时间，按时间排序、去重；
3. 风速按风机分段函数折算容量因子：

\[
CF_w(v)=
\begin{cases}
0, & v<3 \text{ 或 } v>25\\
\dfrac{v^3-3^3}{11^3-3^3}, & 3\le v<11\\
1, & 11\le v\le 25
\end{cases}
\]

4. 光伏按 `GHI / 1000 × 0.82` 折算，裁剪到 `[0,1]`；
5. 电价按小时映射 07 模板：00—08 谷、08—17 平、17—21 峰、21—24 平；
6. 同时保留原始 `ghi_wm2`、`temp_c`，供机器学习迁移使用。

### 4.4 场景 B 构造

`load_scenario_b()` 读取 05 的风、光、负荷，按 50 MW、80 MW 基准容量归一化为 CF，电价同样用 07 模板；05 没有气象列，因此 `ghi_wm2/temp_c` 为 `None`。

### 4.5 数据体检

`src/quality.py` 的 `inspect_bytes()` 对上传的 CSV/XLSX 做规则化体检：

- 文件大小、行数、列数；
- 时间列识别与解析；
- 采样间隔、覆盖率、缺口数量；
- 重复时间戳；
- 数值缺失；
- 物理范围（风速、GHI、温度、负荷、SOC 等）；
- 综合评分与状态：`usable` / `usable_with_warnings` / `unusable`；
- 阻断项与提示项清单、列映射、前 5 行预览。

这一步是“上传即体检”，不是简单的文件预览；它为后续计算提供一个可解释的数据质量门槛。

## 5. 仿真模型

### 5.1 决策变量与边界

\[
x=[C_w,C_{pv},C_b,E_b]
\]

| 变量         | 含义   | 单位  | 下界  | 上界  |
| ---------- | ---- | ---:| ---:| ---:|
| \(C_w\)    | 风电容量 | MW  | 0   | 300 |
| \(C_{pv}\) | 光伏容量 | MW  | 0   | 300 |
| \(C_b\)    | 储能功率 | MW  | 0   | 150 |
| \(E_b\)    | 储能容量 | MWh | 0   | 600 |

储能时长约束：\(2 \le E_b/C_b \le 6\)（\(C_b>0\) 时）。外网通道固定 70 MW。

### 5.2 目标函数

最小化年化总成本：

\[
J = C_{ann}+C_{om}+C_{grid}-R_{export}+C_{carbon}
+\lambda_{cur}E_{cur}+\lambda_{soc}E_{soc}+\lambda_{end}E_{end}
\]

- \(C_{ann}=CRF(i,N)\cdot CAPEX\)，\(i=8\%\)，\(N=25\)；
- \(CRF=\dfrac{i(1+i)^N}{(1+i)^N-1}\)；
- \(CAPEX=6500\cdot 1000\cdot C_w+3500\cdot 1000\cdot C_{pv}+1200\cdot 1000\cdot E_b\)（元）；
- \(C_{om}=1.5\%\cdot CAPEX\)；
- \(C_{grid}=\sum_t p_t^{buy}G_t^{buy}\Delta t\)；
- \(R_{export}=0.35\sum_t G_t^{sell}\Delta t\)；
- \(C_{carbon}=0.5703\cdot 80\cdot E_{grid}^{buy}\)；
- \(\lambda_{cur}=0.05\) 元/kWh，\(\lambda_{soc}=0.10\) 元/kWh，\(\lambda_{end}=50\) 元/kWh；
- 失负荷在主模型中是硬约束，优化适应度中另加 \(10^7\) 元/MWh 惩罚。

### 5.3 功率平衡

逐时平衡式：

\[
P_t^{wind}+P_t^{pv}+P_t^{dis}+G_t^{buy}+E_t^{ens}
= L_t+P_t^{ch}+G_t^{sell}+E_t^{cur}
\]

其中 \(E^{ens}\) 是失负荷，\(E^{cur}\) 是弃风弃光；所有功率单位 MW，时间步长 1 h，所以功率数值等于该小时电量 MWh。

### 5.4 规则调度

`simulate()` 的实现顺序：

**新能源富余（\(P^{wind}+P^{pv}\ge L\)）**

1. 计算富余功率；
2. 若储能未满，按 `min(富余, 充电功率上限, 剩余容量/效率)` 充电；
3. 剩余先上网，超过 70 MW 的部分弃电。

**新能源不足（\(P^{wind}+P^{pv}<L\)）**

1. 若为谷段（电价 ≤ 0.40）且储能低于 80%，电网优先供负荷，剩余通道容量给储能充电；
2. 否则先放储能，再购电，超过 70 MW 的部分记为失负荷；
3. 谷段充电会增加购电成本，不会“免费充电”。

**SOC 更新**

\[
SOC_{t+1}=SOC_t+\frac{\eta P_t^{ch}\Delta t}{E_b}
-\frac{P_t^{dis}\Delta t}{\eta E_b}
\]

硬边界夹紧到 `[0.10, 0.95]`；软区间 `[0.30, 0.80]` 的越界电量按 0.10 元/kWh 计罚；初始 SOC 0.55，末期偏离 0.55 的部分按 50 元/kWh 计罚。

### 5.5 年化与指标

- 周期成本 = 周期变量成本 + 年化固定成本 × `n/8760`；
- 年化成本 = 年化固定成本 + 周期变量成本 × `8760/n`；
- LCOE = 年化成本 / 年化负荷电量 / 1000（元/kWh）；
- 弃电率 = 弃电量 / 新能源可发电量；
- 绿电占比 = 1 − 外网购电 / 负荷电量；
- 供电可靠率 = 1 − 失负荷 / 负荷电量；
- SOC 软区间占比 = SOC 在 30%–80% 的小时数 / 总小时数；零储能时记为 0，不按 100% 处理。

## 6. 优化算法

### 6.1 适应度

\[
fitness = C_{annual} + 10^7 \cdot E_{ens} + 10^6 \cdot V_{duration}
\]

其中 \(V_{duration}\) 是储能时长越界量（小时）。每次评估都跑完整 5832 小时仿真。

### 6.2 PSO

标准粒子群：

\[
v_i^{k+1}=w v_i^k+c_1r_1(pbest_i-x_i^k)+c_2r_2(gbest-x_i^k)
\]

\[
x_i^{k+1}=x_i^k+v_i^{k+1}
\]

- 惯性权重 \(w\) 从 0.9 线性降到 0.4；
- \(c_1=c_2=1.5\)；
- 初始化在边界内均匀采样；
- 每次更新后做边界裁剪和 `repair()`。

### 6.3 GWO

灰狼算法用 α、β、δ 三只头狼引导：

\[
D=|C\cdot X_p-X|,\quad X'=X_p-A\cdot D
\]

\[
A=2a r_1-a,\quad C=2r_2
\]

收敛因子 \(a\) 从 2 线性降到 0；每只狼向三只头狼移动后取平均，再做修复。

### 6.4 修复算子

`repair(x)`：

- 把四个容量裁剪到边界；
- 若 \(C_b=0,E_b>0\)，把 \(C_b\) 设为 \(E_b/4\)；
- 若 \(C_b>0,E_b=0\)，把 \(E_b\) 设为 \(2C_b\)；
- 把 \(E_b\) 限制在 `[2C_b, 6C_b]` 与 `[0,600]` 的交集。

这样避免 GWO 早期出现“有储能容量但没有功率”的不可行解。

### 6.5 复现命令

```powershell
python -m src.optimize --scenario A --algo pso --particles 30 --iters 30 --seed 3
python -m src.optimize --scenario A --algo gwo --particles 30 --iters 30 --seed 3
python -m src.optimize --scenario B --algo pso --particles 20 --iters 20 --seed 5
```

## 7. 机器学习模块

### 7.1 任务定义

用外部公开光伏数据训练：

\[
\widehat{CF}_{pv}=f(\text{辐照度},\ \text{气温},\ \text{时刻})
\]

把模型迁移到 03 场景的 GHI/温度，得到 ML 口径的光伏 CF，再与物理口径 `GHI/1000×0.82` 对照。

### 7.2 数据

- 数据源：Kaggle **Solar Power Generation Data**（Ani Kannal），Plant 1；
- 发电文件 68,778 行、22 台逆变器、15 分钟级；
- 气象文件 3,182 行，字段含辐照度、环境温度、组件温度；
- 按时间聚合逆变器 AC 功率，峰值约 29.15 MW，按 30 MW 装机归一化；
- 时间解析必须 `dayfirst=True`（原始日期为 `dd-mm-yyyy`）；
- 训练样本 3,157 行，按日期前 80%/后 20% 切分，训练 2,487、测试 670。

### 7.3 模型与特征

- 模型：`RandomForestRegressor(n_estimators=240, max_depth=12, min_samples_leaf=8, max_features=0.9, n_jobs=1, random_state=42)`；
- 特征：辐照度（kW/m²）、环境温度（℃）、时刻 sin/cos；
- 目标：AC 功率 / 30 MW，裁剪到 `[0,1]`；
- 外部测试集：MAE 0.0077，RMSE 0.0156，R² 0.9964；
- 同测试集物理基线：MAE 0.0379，RMSE 0.0615。

### 7.4 迁移结果

在 03 场景 5832 小时上：

- ML 平均 CF 0.2688，物理平均 CF 0.2336；
- 两者 MAE 0.0352，最大差 0.1069，相关系数 0.9997；
- 基准 50/80/20/80 方案：物理口径年化 21,340 万元、LCOE 0.503；ML 口径 19,643 万元、LCOE 0.463；
- 差异主要来自 ML 在相同 GHI 下给出更高的 CF，不代表真实现场增益。

### 7.5 定位

ML 模块是**迁移敏感性分析**，不是目标电站的功率预测：

- 外部数据只有 33 天，位于印度，和江苏沿海项目存在气候、组件、安装角度的域偏移；
- 主结果仍使用物理口径；
- 页面与报告都明确标注“外部数据训练、03 数据推理”。

| `created_at`                                              | UTC 时间    |
| `scenario`                                                | 场景名       |
| `algorithm`                                               | PSO/GWO   |
| `c_w/c_pv/c_b/e_b`                                        | 优化容量      |
| `annual_cost/lcoe/curtail_rate/soc_in_band_ratio/ens_mwh` | 关键指标      |
| `payload`                                                 | 完整结果 JSON |

数据库只存运行摘要，不存 5832 点时序；原始数据和结果文件仍在 `data/` 下。这样 SQLite 文件很小，迁移时也只需要换数据访问层。

**MySQL 说明**：当前实现是 SQLite；`db.py` 的接口按“保存/列表”拆分，服务器要换 MySQL 需要把 `sqlite3` 连接替换为 SQLAlchemy 或 MySQL 驱动，当前版本尚未接入。

## 13. 设计取舍

1. **为什么用规则调度而不是 LP 全局调度**：规则调度可以直接嵌入 PSO/GWO 的每次评估，逻辑透明、容易解释；LP 需要处理充放电互补、效率非线性和 SOC 线性化，当前版本只保留 HiGHS 作为后续下界工具。
2. **为什么用 PSO/GWO 而不是梯度法**：目标函数含规则分支、SOC 夹紧、弃电和罚项，不可微；启发式算法更适合黑箱评估。
3. **为什么零储能是最优**：外网 70 MW 可以保供，储能投资高，长时段弃电无法靠短时储能消除；这是成本优先口径下的经济结果，不是约束遗漏。
4. **为什么场景 A/B 不合并**：两份数据的负荷、温度、风速不一致，按行合并会制造虚假的时间对应关系；分别计算并在结果中注明口径更可靠。
5. **为什么 ML 只做对照**：外部数据域偏移明显，模型不能替代物理折算；它的价值是验证“公开数据训练 + 本项目推理”的完整链路。
