# 机器学习：外部光伏数据训练与 03 数据迁移

## 1. 为什么这样做

课程要求“选用网络上的数据集，训练一份机器学习，再用这个去分析给出的数据”。教师给的 03 数据只有 5832 小时、8 个月，直接切分训练再测试仍然是同一电站、同一气候，不能说明“用了网络数据”。

因此本项目选一个公开光伏数据集训练 **容量因子（CF）回归模型**，再把模型迁移到教师 03 数据的 GHI、温度上，回答两个问题：

1. 外部数据学到的“辐照度/气温 → 光伏出力”关系，能否迁移到 03 数据？
2. 如果按外部模型的 CF 重跑规则调度，成本、弃电、绿电占比会怎样变化？

这不是把外部数据当作目标电站的真实功率曲线，而是做 **跨区域迁移对照**。

## 2. 外部数据集

| 项目 | 内容 |
|---|---|
| 名称 | Solar Power Generation Data |
| 作者 | Ani Kannal |
| 原始页面 | https://www.kaggle.com/datasets/anikannal/solar-power-generation-data |
| 使用部分 | Plant 1 的 15 分钟级发电 + 气象观测 |
| 本地文件 | `data/external/solar_power_generation/Plant_1_Generation_Data.csv`、`Plant_1_Weather_Sensor_Data.csv` |
| 时间范围 | 2020-05-15 至 2020-06-17，约 33 天 |
| 样本量 | 22 台逆变器聚合后 3,157 个 15 分钟点 |
| 用途 | 仅课程实验，原始 CSV 不随项目再分发 |

数据下载与检查：

```powershell
python scripts/prepare_external_solar.py
```

脚本会打印形状、时间范围、缺失、辐照度/温度范围，并把文件放到 `data/external/solar_power_generation/`。GitHub 镜像地址写在脚本和该目录的 README 中。

## 3. 特征、目标与切分

- 目标：`cf = 聚合 AC_POWER / 30 MW`，裁剪到 `[0, 1]`。
  - 30 MW 是 Plant 1 的近似装机（22 台约 1.4 MW 逆变器，聚合峰值 29.15 MW）。
- 特征：
  - `irradiance_kw_m2`：气象传感器辐照度，W/m² 除以 1000；
  - `ambient_temp_c`：环境温度；
  - `hour_sin`、`hour_cos`：时刻周期编码。
- 模型：`RandomForestRegressor(n_estimators=240, max_depth=12, min_samples_leaf=8, n_jobs=1)`。
  - `n_jobs=1` 是为了避开 Windows 沙箱禁止命名的管道问题，不影响模型形式。
- 切分：按日期前 80% 训练、后 20% 测试，避免同一小时泄漏。
  - 训练 2,487 行（05-15 至 06-10）
  - 测试 670 行（06-11 至 06-17）

训练命令：

```powershell
python -m src.ml.pv --train
```

产物：

- `models/pv_cf_model.joblib`
- `models/pv_cf_metadata.json`
- 元数据包含数据集、特征、切分、测试指标和训练时间。

## 4. 外部测试集结果

| 指标 | 随机森林 | 物理基线 `irradiance×0.82` |
|---|---:|---:|
| MAE | **0.0077** | 0.0379 |
| RMSE | **0.0156** | 0.0615 |
| R² | **0.9964** | — |

外部测试集拟合很好，但这只能说明模型学到了这个电站的出力形状；不能说明它适合 03 电站。真正的检验在下一节。

## 5. 迁移到 03 数据

把 03 的 GHI（W/m²）和温度输入模型，得到逐时 `pv_cf_ml`，与现有物理折算 `GHI/1000×0.82` 对比：

| 指标 | 数值 |
|---|---:|
| 03 小时数 | 5,832 |
| 物理 CF 均值 | 0.2336 |
| ML CF 均值 | 0.2688 |
| 平均绝对差 MAE | 0.0352 |
| 最大绝对差 | 0.1069 |
| 两条曲线相关系数 | 0.9997 |

ML 曲线整体比物理折算高约 15%，形状几乎一致。原因主要是外部模型在 30 MW 电站上学到的温度/辐照响应更“乐观”，而 03 的 GHI 上限只有 900 W/m²，输入落在训练分布的低端；这不代表 03 真实光伏一定多发出 15%。

## 6. 用 ML 曲线重跑基准方案

基准容量 50 MW 风 / 80 MW 光 / 20 MW·80 MWh 储，场景 A：

| 指标 | 物理口径 | ML 迁移口径 | 变化 |
|---|---:|---:|---:|
| 年化总成本（万元/年） | 21,340.1 | 19,643.4 | −1,696.7（−7.95%） |
| LCOE（元/kWh） | 0.503 | 0.463 | −0.040 |
| 弃电率 | 0.00% | 0.00% | 0 |
| 绿电占比 | 53.2% | 55.8% | +2.5 个百分点 |

结论：ML 曲线使光伏电量增加，购电成本下降，因此年化成本和 LCOE 下降；弃电仍为 0，因为外网 70 MW 和储能把富余电量吸收/送出。这个结果只能作为“外部模型迁移的敏感性分析”，不能替代物理口径的主结论。

## 8. 局限与答辩口径

1. **域偏移**：外部电站位于印度，目标数据位于江苏沿海；气候、组件、逆变器效率不同。
2. **样本短**：外部数据只有 33 天，不能覆盖全年季节变化；03 也只有 1–8 月。
3. **容量假设**：30 MW 是近似装机，CF 的绝对值会受该假设影响；但同一模型内部比较仍有效。
4. **模型只做光伏**：风电仍用物理折算；没有用外部数据训练风电模型。
5. **不是主结论**：平台主结果仍是物理折算 + 规则调度 + PSO/GWO；ML 页面是“外部数据迁移分析”。

答辩时建议表述：

> 我们用 Kaggle 公开光伏数据训练了一个容量因子回归模型，在外部测试集上 R² 为 0.996；把它迁移到教师 03 数据后，ML 曲线与物理曲线的相关系数为 0.9997，平均 CF 从 0.234 提高到 0.269。用 ML 曲线重跑基准方案，年化成本从 2.13 亿元降到 1.96 亿元。这个结果说明外部数据可以提供参考，但存在明显域偏移，因此我们保留物理口径作为主结果，把 ML 作为对照分析。

```powershell
# 4. 启动后端，打开机器学习页
deploy\start.ps1

```
